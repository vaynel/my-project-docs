# MyFin V2.0 자동매매 룰 정의서

> **목적:** 사용자가 설정할 수 있는 자동매매/알림 룰의 유형, 동작 방식, 데이터 구조, 실행 로직을 정의합니다.
> **저장 방식:** `trading_rules` 테이블의 `conditions`(JSONB), `actions`(JSONB)에 저장
> **확장 원칙:** 룰 유형 추가 시 이 문서에 섹션을 추가하고, 백엔드 Evaluator 클래스를 구현합니다.

---

## 룰 식별자 (`conditions.rule_type`)

| rule_type | 한글명 | 방향 | 구현 상태 |
|---|---|---|---|
| `TRAILING_STOP` | 매매룰 (트레일링 스탑) | 매도/알림 | 🔲 미구현 |
| `PRICE_RISE_ALERT` | 상승 알림룰 | 알림 전용 | 🔲 미구현 |
| `PRICE_BUY` | 매수룰 | 매수 | 🔲 미구현 |
| `MA_CROSS` | MA 교차 (기존) | 매수/매도 | ✅ 기존 |

> **기존 `MA_CROSS`·`RSI`·`BOLLINGER_BAND`·`PRICE_BREAKOUT`은 `conditions.indicator` 기반 레거시 룰.
> 신규 룰은 `conditions.rule_type`을 직접 사용.**

---

## 1. 매매룰 — 트레일링 스탑 (`TRAILING_STOP`)

### 1.1 개요
매입 이후 **최고가를 자동 추적**하다가, 최고가 대비 n% 이하로 하락하면 매도(또는 알림)합니다.
"내가 산 금액부터 최고가"를 기준점으로 삼아 손익을 보호합니다.

### 1.2 동작 흐름
```
1. 최초 기준가 = max(매입평균가, 동기화된 현재가)
2. 매 동기화 시: 최고가 갱신 → Redis에 account:{id}:high_price:{ticker} 저장
3. 조건 체크: current_price <= high_price × (1 - drop_pct/100)
4. 조건 충족 시:
   · execution_mode = REAL        → 시장가 매도 주문 실행
   · execution_mode = NOTIFY_ONLY → 설정된 채널로 알림 발송
5. 실행 후 룰 비활성화 (재실행 방지)
```

### 1.3 데이터 구조

```json
// conditions
{
  "rule_type": "TRAILING_STOP",
  "ticker":    "005930",
  "drop_pct":  5.0         // 최고가 대비 하락 기준 (%)
}

// actions
{
  "order_side":     "SELL",
  "amount_type":    "ALL",      // 전량 매도 (향후 PERCENTAGE 지원 예정)
  "execution_mode": "REAL",     // "REAL" | "NOTIFY_ONLY"
  "notification": {             // 선택
    "discord": "https://...",
    "slack":   "https://..."
  }
}
```

### 1.4 최고가 추적 키 설계
```
Redis Key:  hl:{account_id}:{ticker}
Value:      최고가 (float, 원)
TTL:        없음 (룰 비활성화 시 삭제)
갱신 시점:  실시간 동기화 또는 스케줄 동기화마다 current_price > stored_high 이면 갱신
```

### 1.5 엣지 케이스
| 상황 | 처리 |
|---|---|
| 매입평균가 없음 (포지션 없음) | 룰 스킵, WARNING 로그 |
| 현재가 = 0 (장 마감/조회 실패) | 스킵, 다음 동기화에서 재시도 |
| 이미 손절선 이하에서 룰 생성 | 생성 시점 현재가를 기준 최고가로 설정 |

## 2. 상승 알림룰 (`PRICE_RISE_ALERT`)

### 2.1 개요
지정 종목이 기준가 대비 n% 이상 상승하면 알림을 발송합니다.
**매수/매도 주문 없음 — 알림 전용.**

### 2.2 동작 흐름
```
1. 기준가 = conditions.reference_price (룰 생성 시 입력값)
   또는 reference = "PURCHASE" → 매입평균가 자동 사용
2. 조건 체크: current_price >= reference_price × (1 + rise_pct/100)
3. 조건 충족 시: 설정된 채널로 알림 발송
4. 알림 발송 후 룰 비활성화 (1회성) 또는 반복 설정 여부에 따라
```

### 2.3 데이터 구조

```json
// conditions
{
  "rule_type":       "PRICE_RISE_ALERT",
  "ticker":          "005930",
  "rise_pct":        10.0,           // 상승 기준 (%)
  "reference":       "PURCHASE",     // "PURCHASE"(매입가) | "CURRENT"(생성시점 현재가)
  "reference_price": 72400           // reference=CURRENT 시 저장, PURCHASE 시 null
}

// actions
{
  "execution_mode": "NOTIFY_ONLY",   // 항상 NOTIFY_ONLY
  "repeat":         false,           // true: 알림 후 재활성, false: 1회 후 비활성
  "notification": {
    "discord": "https://...",
    "slack":   "https://..."
  }
}
```

### 2.4 기준가 결정 로직
```python
if conditions["reference"] == "PURCHASE":
    # 계좌 포지션에서 매입평균가 조회
    avg_cost = get_avg_cost(account_id, ticker)
    reference_price = avg_cost
elif conditions["reference"] == "CURRENT":
    # 룰 생성 시점 현재가 (DB에 저장됨)
    reference_price = conditions["reference_price"]
```

## 3. 매수룰 (`PRICE_BUY`)

### 3.1 개요
지정 종목이 **사용자가 입력한 목표가 이하로 하락**하면 자동 매수합니다.
매수 금액은 **잔고 비율(%)** 또는 **고정 금액(원)** 중 선택합니다.

### 3.2 동작 흐름
```
1. 조건 체크: current_price <= conditions.target_price
2. 매수 수량 계산:
   a. amount_type = "PERCENTAGE"
      buy_amount = available_balance × (value / 100)
      buy_qty    = floor(buy_amount / current_price)
   
   b. amount_type = "FIXED_AMOUNT"
      buy_amount = min(value, available_balance)   ← 잔고 검증
      buy_qty    = floor(buy_amount / current_price)
      
3. buy_qty < 1 → 스킵, WARNING 로그 ("매수 가능 수량 없음")
4. 주문 실행 (시장가 매수)
5. 룰 비활성화 (1회 매수 후 종료 기본값)
   → repeat=true 이면 재활성화 허용
```

### 3.3 데이터 구조

```json
// conditions
{
  "rule_type":    "PRICE_BUY",
  "ticker":       "005930",
  "target_price": 70000         // 이 가격 이하로 떨어지면 매수
}

// actions
{
  "order_side":     "BUY",
  "amount_type":    "PERCENTAGE",  // "PERCENTAGE" | "FIXED_AMOUNT"
  "value":          10,            // % 또는 원(KRW)
  "execution_mode": "REAL",        // "REAL" | "NOTIFY_ONLY"
  "repeat":         false,
  "notification": {
    "discord": "https://..."
  }
}
```

### 3.4 잔고 검증 로직
```python
available = get_available_balance(account_id)  # pymn_alow_amt

if actions["amount_type"] == "PERCENTAGE":
    buy_amount = available * (actions["value"] / 100)
elif actions["amount_type"] == "FIXED_AMOUNT":
    requested  = actions["value"]
    if requested > available:
        logger.warning(f"요청금액({requested}) > 가용잔고({available}), 가용잔고로 매수")
    buy_amount = min(requested, available)

buy_qty = int(buy_amount // current_price)

if buy_qty < 1:
    # 알림만 가능한 경우 알림 발송 후 스킵
    raise InsufficientBalanceError(f"매수 불가: {available=} {current_price=}")
```

### 3.5 엣지 케이스
| 상황 | 처리 |
|---|---|
| 잔고 부족으로 최소 1주 매수 불가 | 룰 스킵, 알림 채널로 "잔고 부족" 알림 |
| 목표가가 현재가보다 높음 (즉시 발동) | 룰 생성 시 경고 표시 (UI), 생성은 허용 |
| amount_type=FIXED_AMOUNT, value > 잔고 | 가용잔고 전액으로 축소 매수 |

## 4. 공통 필드 정의

### 4.1 `execution_mode`
| 값 | 동작 |
|---|---|
| `REAL` | 실제 브로커 API 호출, 주문 실행 |
| `NOTIFY_ONLY` | 주문 없음, 알림만 발송 |
| `PAPER` | `is_paper_mode=true`, 가상 주문 기록 |

### 4.2 `notification` 구조
```json
{
  "discord":          "https://discord.com/api/webhooks/{id}/{token}",
  "slack":            "https://hooks.slack.com/services/{T}/{B}/{token}",
  "telegram_token":   "bot{token}",
  "telegram_chat_id": "-100{chat_id}"
}
```

### 4.3 `repeat` 필드
| 값 | 동작 |
|---|---|
| `false` (기본) | 1회 실행/알림 후 `is_active = false` |
| `true` | 재활성화하여 반복 감시 (현재 미구현, Phase 4) |

## 5. Evaluator 클래스 설계

```python
# backend/app/services/rule_evaluator.py

class RuleEvaluator:
    """룰 유형별 평가 로직 디스패처."""

    EVALUATORS = {
        "TRAILING_STOP":    TrailingStopEvaluator,
        "PRICE_RISE_ALERT": PriceRiseAlertEvaluator,
        "PRICE_BUY":        PriceBuyEvaluator,
        # 기존 레거시
        "MA_CROSS":         MaCrossEvaluator,
        "RSI":              RsiEvaluator,
    }

    async def evaluate(self, rule: TradingRule, context: EvalContext) -> EvalResult:
        rule_type = rule.conditions.get("rule_type") or rule.conditions.get("indicator")
        evaluator_cls = self.EVALUATORS.get(rule_type)
        if not evaluator_cls:
            raise ValueError(f"Unknown rule_type: {rule_type}")
        return await evaluator_cls().evaluate(rule, context)


@dataclass
class EvalContext:
    account_id:        int
    ticker:            str
    current_price:     Decimal
    avg_cost:          Decimal | None
    available_balance: Decimal
    high_price:        Decimal | None   # Redis에서 조회 (TRAILING_STOP용)


@dataclass
class EvalResult:
    should_execute: bool
    action_type:    str       # "BUY" | "SELL" | "NOTIFY"
    reason:         str
    quantity:       int | None = None
    price:          Decimal | None = None
```

## 6. 감시 주기 설계

### 6.1 주기별 역할 분리

| 태스크 | 주기 | API | 룰 평가 | 잔고 갱신 |
|---|---|---|---|---|
| `watch_prices_and_evaluate` | **1분** (장 중) | `ka10001` (종목별) | ✅ | 현재가만 |
| `sync_realtime_accounts` | 5분 (장 중, opt-in) | `kt00004` (계좌전체) | ❌ | ✅ 수량·잔고 |
| `collect_balance_snapshots` | 일 1회 16:05 KST | `kt00004`+`kt00001` | ❌ | ✅ 스냅샷 이력 |

### 6.2 룰 유형별 감시 세부

| 룰 유형 | 감시 주기 | 필요 데이터 | 특이사항 |
|---|---|---|---|
| `TRAILING_STOP` | **1분** | `ka10001` 현재가 + Redis 최고가 | 최고가 매 분 갱신 필요 |
| `PRICE_RISE_ALERT` | **1분** | `ka10001` 현재가 + avg_cost(DB) | 보유 종목만 해당 |
| `PRICE_BUY` | **1분** | `ka10001` 현재가 + `kt00001` 가용잔고 | **미보유 종목도 감시** |

### 6.3 평가 응답 시간 목표

```
목표: 룰 발동 조건 충족 → 주문/알림 발송까지 ≤ 90초

실제 경로:
  가격 변동 발생
    └─ 최대 60초 대기 (다음 1분 Beat 도착)
    └─ ka10001 조회 (~0.5초)
    └─ 룰 평가 (<10ms)
    └─ 주문 실행 or 웹훅 발송 (~1초)
  총: 최대 ~62초 → ✅ 목표 달성

※ 10초 이내 대응이 필요한 경우:
   WebSocket 실시간 시세 연동 필요 (Phase 2, KIS WS API)
```

> **현재 구현 범위:** 1분 단위 Celery Beat 기반 감시 (Phase 1)
> **Phase 2:** KIS/키움 WebSocket 시세 연동 → 틱 단위 실시간 감시 (미구현)

## 7. `PRICE_BUY` 특이사항 — 미보유 종목

`PRICE_BUY`는 **아직 보유하지 않은 종목**도 타겟이 될 수 있습니다.
이 경우 `account_positions`에 해당 종목이 없으므로, 별도 현재가 조회가 필요합니다.

```python
# 현재가 조회 우선순위:
1. account_positions.current_price (보유 중이면 우선)
2. 없으면 ka10001 API 직접 호출 (별도 비용 발생)
   → rate limit 고려: 한 번에 최대 5종목 병렬 조회 권장
```
